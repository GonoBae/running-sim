# 프로젝트 맥락

## 서비스 기획 문서

2026-10-02 대화를 반영한 [서비스 기획 초안](SERVICE_PLAN.md)에 화면, 실행 규칙, 첫 버전의 제안 범위와 완료 기준을 정리했습니다. 사용자와 확인한 핵심은 실제 경로를 달리는 3D 러너를 관찰하는 경험입니다. 첫 시범 장소는 김해 롯데가든파크 주변 트랙이며 주변 풍경은 제외합니다. 트랙의 정확한 형태와 길이는 아직 확인하지 않았습니다.

## 배경과 방향

사용자는 시뮬레이션 개발 경험이 있고 러닝을 좋아합니다. 취미로 간간히 개발하면서 포트폴리오를 만들고, 향후 웹·백엔드·클라우드 개발 영역으로 지원 범위를 넓히려 합니다. 새로운 연구 전체를 수행하기보다는 검증 가능한 범위를 정해 구현하는 것이 목표입니다.

전문 연구용 선행 사례의 존재만으로 개인 포트폴리오의 개성을 부정하지 않습니다. 사용자 경험, 실험 재현 과정, 모델의 한계 설명과 구현 완성도가 중요한 평가 요소입니다. 예측 정확도나 취업 성과는 아직 검증되지 않았습니다.

## 목표와 사용자 조건

- 신체 치수: 키, 몸무게, 다리 길이, 상체 길이, 어깨너비, 발 크기 등을 직접 설정하고 3D 외형에 반영합니다.
- 근골격 특성: 사용자가 입력하며 자동 추정은 필수가 아닙니다.
- 비교 대상: 달리기 조건에 따른 에너지 소모, 심박 반응, 피로, 10km·42.195km 완주 시간입니다.
- 달리기 **동작 형태는 고정**한다는 사용자 조건을 유지합니다.
- 체형 조작과 시나리오 비교의 재미도 목표입니다. 단순 기록 계산기로 목표를 축소하지 않습니다.

## 앞으로 설계할 사항

동작 형태 고정이 반복 주기 고정까지 의미하는지 정해야 합니다. 반복 주기까지 고정하면 케이던스가 고정되며, 속도까지 고정하면 거리별 완주 시간은 이미 정해집니다. 동작 형태를 유지하면서 반복 속도와 지속 가능한 속도를 어떻게 변화시킬지는 향후 설계 과제입니다.

체형 변경에 따른 출력 차이는 곧바로 개인 체형 변경의 인과 효과를 의미하지 않습니다. 에너지·심박·피로·성능 모델 간 연결의 타당성과 개인 수준 적용 가능성은 별도로 검증해야 합니다.

## 첫 검토 후보: 추가 다리 질량 실험

[Running with added leg mass](REFERENCES.md#1-running-with-added-leg-mass-2023)의 공개 실험을 재현하는 방안을 검토합니다. 아직 데이터 파일을 내려받거나 분석하지 않았으며 모델 구현도 시작하지 않았습니다. 이 후보는 확정 사양이 아닙니다.

후속 검토 시 확인할 항목:

1. 실제 파일 구조, 단위, 추가 질량의 크기·위치, 측정 절차와 결측값을 확인합니다.
2. 재현할 관측량과 기준 조건을 정합니다. 고정 속도 실험 결과를 장거리 완주 시간으로 바로 일반화하지 않습니다.
3. 논문 계산식, 기준 모델, 평가 지표, 허용 가능한 오차와 불확실성 보고 방법을 정합니다.
4. 참가자 단위 데이터 분할과 재현 가능한 실험 기록을 설계합니다.
5. 질량을 추가한 실험과 자연적인 신체 치수·근육량 차이의 해석을 구분합니다.

## 검증 원칙

- 논문에 근거한 계산식과 가정을 명시합니다.
- 공개 데이터로 실험을 재현하고, 데이터 버전·출처·라이선스를 기록합니다.
- 모델을 맞춘 자료에서의 오차와 미관측 자료 예측 오차를 구분합니다.
- 실제 측정과 대리지표를 구분하고, 적용 범위와 오차를 결과와 함께 제시합니다.
- 공개 코드가 있어도 원본 데이터까지 공개되어 있다고 가정하지 않습니다.

## 구현 방향과 미정 사항

기술 스택의 권장 조합과 단계별 도입 계획은 [기술 설계와 도구 선정안](TECH_PLAN.md)에 정리했습니다. 웹은 TypeScript·React·Three.js 계열, 캐릭터는 Blender, 후속 계산은 Python·FastAPI를 제안합니다. 사용자 경험과 기술 검증을 반영하기 전의 선정안이며 확정된 일정이나 구현 완료를 의미하지 않습니다.

사용자는 나이키 런 클럽을 사용합니다. 첫 버전에 앱 연동을 필수로 두지 않는 방향을 제안하며, 기록 파일 보유 여부와 내보내기 가능 여부는 미확인입니다.

사용자는 Supabase와 Vercel을 이미 사용하고 있으며 Vercel은 Pro 플랜입니다. 이 환경을 웹 배포와 후속 기록·파일 저장의 기준으로 활용합니다. Supabase 요금제와 기존 프로젝트의 남은 사용량은 미확인입니다.

남은 결정: 트랙 자료와 거리 기준, 첫 버전의 세부 범위, 첫 실험 범위, 동작 반복 속도 처리, 각 모델의 연결 방식, 기술 스택, 정식 프로젝트 이름, GitHub 원격 저장소 필요 여부와 계정/조직입니다.

## 이번 준비의 범위

독립 로컬 Git 저장소와 문서만 준비합니다. 애플리케이션 코드 작성, 의존성 설치, 대용량 데이터 다운로드, 원격 저장소 생성·푸시, 자동 실행 예약은 범위 밖입니다. Git 작성자 정보는 임의로 설정하지 않습니다. 앱의 저장된 프로젝트 연결도 아직 완료되지 않았습니다.
