# 실제 트랙 러닝 시뮬레이터 기획 초안

작성일: 2026-10-02

이 서비스는 사용자가 설정한 체형의 3D 러너가 실제 경로를 달리는 과정을 관찰하고, 조건을 바꾸어 비교하는 웹 시뮬레이터다. 첫 시범 장소는 김해 롯데가든파크 주변 트랙이며 주변 풍경은 구현하지 않는다. 결과 수치뿐 아니라 트랙 위에서 달리는 경험 자체가 핵심이다.

이 문서는 화면과 기능, 실행 규칙, 개발 순서와 완료 기준을 정의한다. 사용자와 합의된 방향은 아래에 별도로 기록한다. 나머지 세부 사양은 구현을 위한 제안이며 사용자 승인이나 검증을 마친 사실로 취급하지 않는다. 현재는 기획 단계이고 애플리케이션 구현은 시작하지 않는다.

## 확정된 방향

| 항목 | 사용자와 확인한 내용 |
| --- | --- |
| 핵심 경험 | 설정한 러너가 설정한 코스를 실제로 이동하며 달리는 모습을 본다. |
| 코스의 성격 | 가상으로 만든 코스가 아닌 실제 경로를 사용한다. |
| 첫 장소 | 김해 롯데가든파크 주변 트랙이다. 정확한 주행 선과 한 바퀴 길이는 미확인이다. |
| 배경 | 실제 장소의 주변 풍경은 구현하지 않아도 된다. |
| 화면 구성 | 이미지 시안을 통해 왼쪽 트랙 주행과 오른쪽 자세 상세를 동시에 보는 구성을 확인했다. 두 화면은 같은 러너와 시점을 공유하고 재생 조작을 함께 적용한다. |
| 러너 | 신체 치수와 근골격 특성을 직접 설정하는 기존 프로젝트 방향을 유지한다. |
| 캐릭터 형태 | 사람 형태의 전신 러너로 확정했다. 얼굴·복장·사실적 표현 수준은 아직 정하지 않았다. |
| 첫 진입 | 별도의 게임형 캐릭터 커스터마이징 화면에서 캐릭터 설정을 먼저 완료한다. |
| 달리기 동작 | 동작 형태를 고정한다. 반복 속도까지 고정하는지는 아직 정하지 않았다. |
| 보유 앱 | 사용자는 나이키 런 클럽을 사용한다. 기록 파일 보유 및 내보내기 가능 여부는 미확인이다. |
| 현재 작업 | 구체적인 기획과 문서화를 진행한다. |

## 서비스 목표와 단계 구분

장기 목표는 신체 설정, 실제 코스 주행, 에너지 소모와 심박·피로·완주 성능 비교를 하나의 경험으로 연결하는 것이다. 단순한 결과 계산기나 캐릭터 애니메이션만으로 최종 목표를 대체하지 않는다.

첫 버전은 트랙과 러너, 시간과 거리의 일관된 움직임을 완성하는 시각화 단계로 제안한다. 이 단계에서 사용자가 지정한 속도는 입력값이다. 체형 때문에 자동으로 속도가 달라지거나 피로로 느려지는 기능은 포함하지 않는다. 같은 속도와 거리를 지정하면 체형이 달라도 소요 시간은 같다.

후속 단계에서 검증된 신체 반응 모델을 연결한다. 고정 속도에서의 에너지 소모 비교와 지속 가능한 속도에 따른 완주 시간 예측은 서로 다른 기능으로 설계한다. 전자의 검증만으로 후자를 제공하지 않는다.

## 대표 사용 흐름

1. 사용자가 웹에 접속하면 별도의 캐릭터 커스터마이징 화면과 정지한 전신 러너가 표시된다.
2. 캐릭터를 돌려 보며 체형을 조절하고 “이 캐릭터로 시작”으로 설정을 확정한다.
3. 별도의 코스 설정 화면에서 경로를 확인하고 목표 거리 또는 바퀴 수와 페이스를 입력한다.
4. 시작을 누르면 러너가 정해진 출발점에서 트랙을 따라 달린다.
5. 사용자는 추적 시점과 전체 시점을 전환하고, 일시정지하거나 배속을 바꾼다.
6. 목표에 도달하면 달리기가 완료되고 거리, 소요 시간과 완료 바퀴 수가 표시된다.
7. 같은 조건으로 다시 재생하거나 설정 화면으로 돌아가 조건을 바꾼다.

기본 체형과 주행 조건은 즉시 체험할 수 있게 제공하되 실제 사용자의 신체나 운동 능력을 추정한 값으로 표시하지 않는다.

## 화면 구성 제안

데스크톱 브라우저를 첫 지원 환경으로 삼는다. 캐릭터 커스터마이징 → 코스 설정 → 좌우 주행 화면으로 구성한다. 실행·일시정지·결과는 좌우 주행 화면에서 이어간다. 모바일 최적화는 후속 범위로 둔다.

| 영역 | 표시 내용과 동작 |
| --- | --- |
| 상단 | 서비스 이름, 선택된 코스, 준비·달리는 중·일시정지·완료 상태 |
| 캐릭터 커스터마이징 화면 | 첫 진입에 전신 캐릭터를 보며 체형 설정, 완료 후 주행 준비로 이동 |
| 코스 설정 화면 | 트랙 확인과 목표 거리 또는 바퀴 수, 페이스 설정. 체형 재편집은 커스터마이징 화면으로 이동 |
| 왼쪽 트랙 주행 화면 | 단순한 바닥 위 실제 형태의 트랙, 이동하는 러너, 출발선, 진행 방향 |
| 오른쪽 자세 상세 화면 | 같은 러너의 같은 순간 자세를 확대해 표시, 측면·정면·후면 전환과 관절 표시 |
| 화면 내 정보 | 누적 거리, 시뮬레이션 경과 시간, 현재 페이스, 완료 바퀴와 현재 바퀴 진행률 |
| 하단 조작 | 일시정지와 재개, 배속 선택, 처음부터 재생, 카메라 전환 |
| 완료 패널 | 이번 실행 조건과 결과 요약, 다시 재생, 설정 변경 |

러너를 뒤에서 따라가는 시점을 기본으로 제안한다. 전체 시점에서는 트랙과 러너의 위치를 한눈에 볼 수 있어야 한다. 별도 미니맵과 자유로운 카메라 조작은 필요성이 확인된 뒤 추가한다.

왼쪽 트랙 주행과 오른쪽 자세 상세 배치는 사용자의 추가 요청을 반영한다. 두 화면은 동일한 체형과 동작 시점을 공유하고 일시정지·배속·재개를 함께 적용한다. 자세 상세는 동작을 관찰하기 위한 것으로, 자세 교정 점수나 검증되지 않은 관절 분석 수치를 제공하지 않는다. [화면 이미지 시안](images/running-dual-view-v2.png)은 캐릭터·코스 화면과 디자인을 맞춘 검토용이며 트랙 형상과 수치는 예시다.

실행 중에는 체형과 목표 설정을 잠근다. 카메라와 재생 속도만 즉시 바꿀 수 있다. 설정 변경을 선택하면 현재 실행을 종료하고 설정 화면으로 돌아갈 수 있음을 안내한다.

## 첫 버전 기능 범위 제안

### 러너 설정

| 입력 | 단위 | 첫 버전의 반영 방식 |
| --- | --- | --- |
| 키 | cm | 러너의 전체 높이를 변경한다. |
| 몸무게 | kg | 입력값을 보관한다. 외형 대응 규칙은 별도 검증 후 정하며 근육량을 자동 추정하지 않는다. |
| 다리 길이 | cm | 정의한 관절 기준으로 다리 비율을 변경한다. |
| 상체 길이 | cm | 정의한 기준점 사이 상체 길이를 변경한다. |
| 어깨너비 | cm | 어깨 폭을 변경한다. |
| 발 크기 | mm | 발 모델 크기를 변경한다. |

각 길이의 측정 기준과 허용 범위는 러너 모델의 관절 구조를 정한 뒤 확정한다. 키와 각 부위 길이를 독립적으로 무제한 입력하게 하지 않는다. 충돌하는 값은 이유를 표시하고 수정을 요청하며, 입력값을 설명 없이 바꾸지 않는다. 수치 입력과 조절 막대는 같은 값을 표시한다.

근골격 특성은 장기 목표로 유지한다. 근육량·근력 등 실제로 사용할 변수는 계산 모델의 입력 정의와 근거가 확보된 뒤 추가한다. 계산에 쓰이지 않는 값을 필수로 요구하지 않는다.

### 코스

첫 버전은 롯데가든파크 트랙 한 개를 미리 제공한다. 임의 경로를 선택하거나 편집하는 기능은 후속 범위로 둔다. 사용자가 경로를 설정한다는 장기 목표는 유지한다.

트랙 데이터에는 경로 좌표, 출발점, 진행 방향, 거리 기준, 출처와 버전을 포함한다. 한 바퀴 길이, 트랙 폭, 고도는 확인 전까지 임의의 실제 수치로 기재하지 않는다. 차선 구분이 확인되지 않으면 차선을 지어내지 않는다.

지도나 사용자가 제공한 GPS 기록 등 이용 가능한 자료로 경로를 확인한다. 어떤 자료를 채택할지는 이용 조건과 정확도를 확인한 뒤 정한다. 지도상의 경로를 수작업으로 정리했다면 근사 경로임을 표시한다. GPS 기록의 총거리를 트랙의 정확한 공식 길이로 간주하지 않는다.

고도 자료가 없으면 첫 시각화는 평면으로 구성하고 평면화했음을 코스 정보에 표시한다. 실제 경사가 없다고 단정하지 않는다. 배경은 단색 바닥과 최소한의 조명으로 구성하며 건물·나무·사진·로드뷰는 제외한다.

### 주행 조건과 조작

- 목표는 거리 km 또는 바퀴 수 중 하나를 선택한다. 거리 목표는 마지막 바퀴 중간에서도 완료할 수 있고, 바퀴 수는 양의 정수로 입력한다.
- 속도 입력은 러너에게 익숙한 분/km 페이스를 기본으로 제안한다. 내부 이동 계산에는 m/s를 사용한다.
- 첫 실행은 고정 페이스로 진행한다. 준비 동작, 가속·감속, 피로에 따른 속도 변화는 후속 기능이다.
- 배속은 1배·2배·5배·10배를 제안한다. 배속은 관찰에 걸리는 실제 시간만 바꾸고 결과의 시뮬레이션 시간과 거리는 바꾸지 않는다.
- 일시정지하면 거리와 시뮬레이션 시간이 함께 멈춘다. 재개하면 같은 위치에서 이어진다.
- 처음부터 재생하면 같은 입력 조건으로 시간·거리·바퀴 수를 초기화한다.
- 브라우저 탭이 숨겨지면 자동 일시정지하고, 돌아오면 사용자가 재개하도록 제안한다.

### 실행 상태와 오류

| 상태 | 사용자에게 보이는 동작 |
| --- | --- |
| 불러오는 중 | 트랙과 러너 준비 상태를 표시하며 시작을 비활성화한다. |
| 준비 | 입력값이 유효하면 시작할 수 있다. |
| 달리는 중 | 러너가 이동하고 진행 정보가 갱신된다. |
| 일시정지 | 위치와 시간을 유지하고 재개할 수 있다. |
| 완료 | 목표 지점에서 이동을 끝내고 결과를 표시한다. |
| 오류 | 원인을 가능한 범위에서 안내하고 다시 시도할 수 있게 한다. |

숫자가 아니거나 0 이하인 거리·페이스, 부적합한 체형 값은 해당 입력 옆에서 안내한다. 트랙이나 러너를 불러오지 못하면 빈 화면만 남기지 않는다. 3D 표시를 지원하지 않는 환경에서는 지원 브라우저 안내를 제공한다.

## 주행과 계산의 일치 규칙

러너의 위치, 거리, 바퀴 수, 표시 시간은 하나의 시뮬레이션 시간을 기준으로 계산한다. 화면의 초당 그리기 횟수에 따라 러너의 속도가 변해서는 안 된다.

페이스가 p초/km이면 속도는 1000/p m/s다. 시뮬레이션 시간 t초 동안 이동한 거리는 속도 × t로 구하고 목표 거리에서 멈춘다. 트랙 길이가 L이면 완료 바퀴 수는 누적 거리/L의 정수 부분이고, 나머지 거리로 현재 위치를 구한다. 좌표 점의 개수가 아닌 구간 길이를 기준으로 이동시켜 곡선에서도 이동 속도를 유지한다.

예를 들어 6분/km로 1km를 달리면 시뮬레이션 시간은 6분이다. 10배속에서는 중단과 처리 지연이 없다면 약 36초 동안 관찰하게 되지만 결과에는 6분으로 표시한다. 이 예시는 트랙의 실제 길이나 사용자의 기록을 뜻하지 않는다.

동작 형태를 유지하되 반복 속도 조절을 허용하는 방안을 제안한다. 이 방식은 아직 확정되지 않았다. 체형과 이동 속도가 달라져도 발이 과도하게 미끄러지거나 지면을 뚫지 않도록 표현을 조정한다. 반복 속도를 생리학적으로 정확한 케이던스 예측값처럼 표시하지 않는다.

## 결과와 비교 기능

첫 버전의 완료 화면에는 실행한 체형, 코스 버전, 목표, 설정 페이스, 실제 진행 거리, 시뮬레이션 경과 시간과 완료 바퀴 수를 남긴다. 사용자가 중간에 종료했다면 완주 결과와 구분한다.

후속 비교 기능에서는 기준 실행 A를 보관하고 조건을 변경한 실행 B를 비교한다. 같은 코스와 시점으로 나란히 재생하거나 겹쳐 볼 수 있는 방식을 검토한다. 고정 페이스 단계에서는 체형별 완주 성능 차이를 만들어 표시하지 않는다. 생리 모델 도입 후에는 계산에 실제 영향을 주는 입력과 모델 버전을 함께 보여준다.

## 실행 구조와 저장 제안

첫 시각화 버전은 브라우저에서 체형 조절, 3D 표시와 고정 페이스 이동을 처리한다. 사용자는 설치 없이 웹 주소로 접속하는 형태를 목표로 한다. 개발 중에는 로컬에서 실행하고, 공개 배포 시점과 호스팅은 별도로 결정한다.

호스팅 방향은 이후 확인한 기존 사용 환경을 반영해 Vercel Pro로 정리한다. 기록과 파일 저장이 필요해지면 사용 중인 Supabase를 우선 활용한다. 기존 서비스 사용 사실이 첫 버전의 로그인·영구 저장 기능 추가를 의미하지는 않는다. 세부 구성과 비용 조건은 [기술 설계서](TECH_PLAN.md)에 정리한다.

계정 가입과 NRC 연동은 첫 버전의 선행 조건으로 두지 않는다. 첫 버전의 설정과 결과는 현재 세션에서 유지하며 새로고침 후 복구는 보장하지 않는 안을 제안한다. 장기 저장과 공유는 후속 기능으로 설계한다.

검증된 신체 반응 모델을 도입할 때 계산 서버의 필요성을 평가한다. 계산이 오래 걸린다면 서버가 실행 상태와 결과를 관리하고, 브라우저는 계산된 시간별 값을 재생하도록 확장한다. 웹·백엔드·클라우드 포트폴리오 목표는 이 단계에서 연결한다. 특정 기술 스택과 서비스 비용은 아직 확정하지 않는다.

| 데이터 | 보관할 주요 내용 |
| --- | --- |
| 러너 설정 | 치수, 단위, 적용한 외형 규칙 버전 |
| 코스 | 좌표, 거리 기준, 출발점, 방향, 고도 유무, 출처, 버전 |
| 실행 설정 | 러너와 코스의 실행 시작 시점 복사본, 목표, 페이스 |
| 진행 상태 | 시뮬레이션 시간, 누적 거리, 현재 상태 |
| 계산 결과 | 완료 여부, 결과값, 사용한 모델과 적용 범위 |

카메라와 배속은 표시 설정으로 구분하며 신체 조건이나 계산 결과를 변경하지 않는다. 출처가 불분명한 지도 자료나 사용자의 NRC 계정 정보가 필요하다는 가정을 두지 않는다.

## 개발 단계와 완료 기준 제안

첫 실행 검증은 [체형 조절 검증 계획](CHARACTER_VALIDATION.md)에 따른다. 정지한 캐릭터에 설정값을 적용하고 실제 치수와 관절 반영을 확인한 뒤 달리기·좌우 화면·트랙 이동을 연결한다. 코스 자료 조사는 병행할 수 있으나 체형 조절 가능성이 확인되기 전에 주행 화면 완성을 우선하지 않는다.

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1 체형 조절 우선 검증과 코스 조사 | 설정으로 변형 가능한 정지 러너, 치수 검증표와 트랙 자료 | 입력·측정 치수와 관절 위치를 확인해 지원 범위를 정하고, 코스 자료의 출처와 불확실성을 기록한다. |
| 2 핵심 주행 경험 | 한 트랙에서 달리는 웹 화면 | 러너가 경로를 따라 반복 주행하고, 추적·전체 시점과 일시정지·배속·완료가 동작한다. |
| 3 설정과 재실행 | 체형 및 목표 입력 화면 | 입력 오류를 안내하고, 실행 조건이 고정되며, 완료 후 조건을 바꿔 재실행할 수 있다. |
| 4 신체 반응 검증 | 한 가지 검증된 모델과 보고서 | 독립적인 평가 기준으로 오차와 적용 범위를 확인하고 주행 화면에 결과를 연결한다. |
| 5 비교와 서비스 확장 | 실행 비교, 저장, 경로 선택 | 비교 가능한 조건을 명시하고 동일 실행을 다시 재생할 수 있다. 필요에 따라 서버·배포를 확장한다. |

첫 버전 출시는 1~3단계의 완료를 의미한다는 안을 제안한다. 이때 생리학적 시뮬레이션 전체가 완성되었다고 소개하지 않는다. 4단계의 첫 연구 후보는 기존 문서의 추가 다리 질량 실험이며 확정된 것은 아니다. 일정은 코스 자료와 3D 러너 표현을 검증한 뒤 산정한다.

첫 버전은 다음 시나리오로 확인한다.

- 한 바퀴를 완료하면 출발점으로 돌아오고 완료 바퀴 수가 정확히 한 번 증가한다.
- 목표가 바퀴 길이의 배수가 아니어도 목표 거리에서 멈춘다.
- 동일 조건을 1배속과 10배속으로 실행했을 때 최종 거리와 시뮬레이션 시간이 같다.
- 일시정지와 재개, 탭 전환으로 거리나 시간이 갑자기 증가하지 않는다.
- 키와 신체 비율을 변경해도 러너가 트랙을 이탈하거나 지면 아래로 내려가지 않는다.
- 입력 오류와 자료 로딩 실패 시 다음 행동을 알 수 있다.
- 실제 주변 풍경 없이도 트랙의 형태, 진행 방향과 러너 위치를 알아볼 수 있다.

## 남은 결정과 확인 순서

| 순서 | 미정 사항 | 처리 방향 |
| --- | --- | --- |
| 1 | 트랙의 정확한 주행 선, 거리, 출발점, 방향 | 사용 가능한 지도 자료를 우선 조사하고 식별이 어려운 지점만 사용자에게 확인한다. |
| 2 | 외형 모델과 입력 범위 | 모델의 관절과 치수 정의를 확인해 제한을 제안한다. |
| 3 | 달리기 동작의 반복 속도 | 동작 형태 고정 조건 안에서 속도 동기화가 가능한지 검토한다. |
| 4 | 첫 버전의 단계 범위 | 이 문서의 1~3단계 제안을 다음 기획 검토의 기준으로 삼는다. |
| 5 | 생리 모델의 첫 출력 | 데이터와 논문을 검토해 검증 가능한 관측량 하나를 선정한다. |
| 6 | 기술 스택과 배포 | 코스·러너 검증 결과와 지원 기기를 근거로 선정한다. |

NRC 기록 제출은 현재 기획을 계속하기 위한 필수 조건이 아니다. 사용자의 다음 답변을 기다려야만 진행할 수 있는 질문 목록으로 이 표를 사용하지 않는다. 구현 착수 전에는 코스 자료의 이용 조건, 트랙 오차 기준, 지원 환경과 성능 목표를 구체화한다.
