## M01 자세 복사본

> 초기 정적 자세 실험의 계약입니다. 현재 `stages.js`의 상태 저장·버튼과 연결하지 않습니다.

**M01-a/b 구현.** [M01 요구·검수 기준](../02-requirements/REQUIREMENTS.md#r12의-첫-실험-m01)에 사용하는 임시 데이터입니다. 위의 `PoseFrame`과 달리 시각·체형 참조가 없으며, 현재 입력 단위인 도(°)를 그대로 보관합니다.

| 필드 | M01-a 계약 |
| --- | --- |
| `schemaVersion` | `1` · 저장 구조 버전 |
| `modelHash` | 현재 GLB 바이트의 SHA-256 · 표시 이름/남녀 선택값으로 대신하지 않음 |
| `poseDefinitionVersion` | `running-pose-v1` · 관절 의미·축·고정 벌림 변경 시 갱신 |
| `settingsRevision` | 현재 적용한 관리자 설정 변경 번호 · 복원 시 저장본/화면 설정/로컬 최신 설정 일치 검사 |
| `unit` | `deg` · 후속 PoseFrame의 rad 제안과 혼용 금지 |
| `values` | `upperarm_l/r`, `lowerarm_l/r`, `thigh_l/r`, `calf_l/r` 각각의 숫자 · 정확히 8개 키 |

슬롯의 초기값은 `null`이며 값은 불변 복사본으로 다룹니다. 모델 파일·뼈 객체·Quaternion·체형·카메라·시간은 이 구조에 넣지 않습니다.

```ts
// API 사용 예시: getContext는 main.ts의 최신 모델·설정 상태
const store = createPoseSnapshotStore(getContext);
store.save();          // 현재 관절값을 불변 복사본으로 저장
const result = store.restore(); // 전체 검사 후 일괄 복원
// result.ok / result.reason은 pose-snapshot-ui.ts에서 상태 문구로 표시
```

[`running-pose.ts`](../../experiments/model-preview/src/running-pose.ts)의 기존 `set()`은 한 값씩 반올림·범위 보정합니다. 새 `restore()`는 전체를 먼저 검사해 일괄 적용하며, 예외 시 이전 8개 값·뼈 회전·행렬 캐시를 복구합니다. [검사 결과](../05-validation/POSE_SNAPSHOT.md)

| 설계 지점 | 처리와 연결 상태 |
| --- | --- |
| 복사 경계 | 저장 시 새 값 객체 생성 · 복원 때도 새 후보 사용 · 저장본에 UI 참조 연결 금지 |
| 숨긴 관절 | 전체 8개 값을 보관하되 숨긴 항목은 해당 정책의 기본값인지 검사 |
| 설정이 오래된 화면 | 매 검사/클릭마다 최신 설정 읽기 · storage/focus/visibility 이벤트로 상태 갱신 · 읽기 실패도 차단 |
| 모델 교체 경쟁 | 로드 중 적용 차단 · 검사 시작/반영 시 활성 모델·로드 식별자 일치 확인 |
| 원자적 적용 | 유효성 검사 중 변경 없음 → 8개 값 교체 → `apply()` 1회 · 실패하면 이전 값 복구 · 성공 후 숫자/슬라이더 갱신 |
| 후속 동작 생성 | PoseTarget/PoseFrame 연결·단위 변환 별도 설계 · M01을 영구 형식으로 확정하지 않음 |

## 목표 입력·생성 결과 검사 제안

| 검사 | 처리 |
| --- | --- |
| 빈 값·NaN·존재하지 않는 관절 | 저장 거부 · 해당 항목 표시 |
| 각도 제한 | 관리자 게시 버전 기준 검사 |
| 중복 프레임 ID·같은 시각 | 생성 결과의 모호한 순서 거부 · 사용자 시각 입력 요구 아님 |
| 음수 시각·0 이하 주기 | 저장 거부 |
| 반복 경계 | 마지막→처음 연결 구간 별도 검사 |
| 모델·체형·제한 변경 | 호환성 재검사 · 기존 확정 동작 보존 |

중간 동작의 관통·접지는 숫자 범위 검사만으로 통과시키지 않습니다.

## 보관과 통계

| 구분 | 현재 | 제안·남은 결정 |
| --- | --- | --- |
| 모델 파일 | 기본 GLB·동작 JSON · 검사 해시 | 운영 Storage·게시 버전 / 등록 GLB IndexedDB는 이전 시험 |
| 관리자 설정 | 현재 단계 미연결 · 과거 localStorage 코드 보존 | 서버 관리자 권한·게시 버전 |
| 사용자 신체·자세·코스 | `running-sim.stages.v1` · sessionStorage | 계정·영구 저장·소유 권한 |
| 주행 시간·배속 | 화면 메모리 · 재진입/새로고침 시 재시작 | 실행 결과 보관·A/B는 별도 |
| 사용 통계 | 현재 단계 수집 미연결 | 과거 ‘이 설정 적용’ 정적 조합 집계와 동작/주행 이벤트 구분 |

‘많이 사용된 자세’의 과거 로컬 시험은 정적 관절값 조합을 세었습니다. 운영 동작 순위와 프레임별 순위는 집계 단위부터 정해야 합니다.



| 운영 접근 권한 제안 | 사용자 | 관리자 |
| --- | --- | --- |
| 게시 모델·허용 설정 | 읽기 | 검증·게시 |
| 개인 동작·프로필 | 본인 자료만 | 지원 목적 접근 여부 미정 |
| 이용 통계·설정 변경 기록 | 원시 기록 조회 불가 | 권한 확인 후 조회 |
